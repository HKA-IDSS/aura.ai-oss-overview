Aura Project

The Aura.ai project aims to provide continuous authentication in mobility provider phone applications. For this, Machine Learning (ML) mechanisms are being developed, capable of inferring behavioral patterns from users during their interactions with the phone. Such patterns are then compared with the user’s usual behavioral patterns. If there is a match, the user is automatically authenticated without requiring further input. The project was divided into two main subprojects: Continuous Authentication, and Federated Learning. Each subproject features an architecture and some repositories with experimentation, which were made available on this webpage.

The Continuous Authentication (CA) subproject focuses on privacy-preserving, ML-based behavioral authentication for client–server mobility applications. It implements a framework in which behavioral data (e.g., sensor readings and interaction patterns) are preprocessed and encrypted directly on the client's device before being transmitted to the server. The server performs machine-learning inference on encrypted data using homomorphic encryption (HE), enabling continuous authentication without accessing raw behavioral information. The framework integrates:

  • ML-based multi-source behavioral fusion, enabling robust authentication across heterogeneous sensor modalities.
  • Homomorphic encryption allows secure computation on encrypted behavioral embeddings.
  • Zero-knowledge proofs (zk-SNARKs) to ensure classifier decision integrity while preventing manipulation by attackers.
  • A key rollover mechanism to mitigate recently discovered cryptographic vulnerabilities in HE schemes.
  • Within aura.ai, the framework was integrated into a real-world public transport application. This included extending existing OAuth/OpenID-based infrastructures with an authentication proxy, enabling interoperability between different mobility providers while preserving strict privacy boundaries. The system was evaluated in a field test with real users, demonstrating practical feasibility and robustness against impersonation attempts. The code for the full CA framework is currently under submission and will be made publicly available upon completion of the review process.

The Federated Learning (FL) subproject consists of a Data Governance (FML-DG Platform) platform applied to FL, combined with a decentralized preprocessing component. First, the FML-DG platform offers functionality to negotiate the goals and training settings, run the training under those settings, and collect provenance metadata from the process. Then, we also developed an experimental communication framework, where we introduced secure and decentralized preprocessing before the training process (FLTraining-Preprocessing). Finally, in this part we also offer two other interesting projects. We designed a path prediction ML model trained in federated data (Gretel-Pathing). Although the data is unavailable due to privacy reasons, we relied on the public data schema of Matomo. The second is a study in how heterogeneous tabular data affects the quality of ML models, and how to determine the quality of contribution from participants accurately in these heterogeneous scenarios.
